# 虚拟角色 AI 审核与消融实验

用于选择“参考立绘 → 上半身角色包 → App 互动”的模型和制作流程。评测分为两项：比较候选流程的产物，校准 AI 审核员对同一份证据的判断。生成模型、审核模型和人审金标各自留档。

## 题库与实验入口

本文件介绍原有通用角色题库。动作专项另有 18 个检查点，保留不同观测能力、标定和证据类型。直接打开[动作审核规范](motion-review.md)、[动作专项题库](motion-cases.jsonl)与[全流程消融及已运行的实验](experiments/README.md)。两份题库 ID 互不重复；需要同一份端到端清单时，从仓库根目录执行下方命令。独立角色数以机构的实际采集和分组记录为准。

```sh
cat benchmark/cases.jsonl benchmark/motion-cases.jsonl > /tmp/luis-all-cases.jsonl
python3 benchmark/bench.py validate --cases /tmp/luis-all-cases.jsonl
```

## 当前能复现什么

题库有 **26 个检查点、8 个场景组、6 个维度**。开发集 14 项，公开预演集 12 项。每条写明输入、操作、判据、所需证据和是否为硬性验收项。两个分组都随代码公开，真正的盲测集需另行封存。题库定义不等于已执行或已标注的数据集。

已执行一次 **BW02 胸针位置的合成视觉测试**。两份 480 × 360 候选画面只有胸针佩戴位置不同。把文件匿名后，两个独立的 AI 会话各看一份候选和同一张标注参考图。一个判定在角色左胸，另一个指出胸针换到右胸。揭盲后，两项判定均符合构造时设定的结果。这里有 **1 个独立场景、1 个检查点、2 个候选产物**。本次使用当前 Codex 的图像盲审会话和 BW02 专项指令，未记录服务端模型快照。通用 API 适配器另做了本地协议测试。

## 第一轮从哪里开始

先采集题库中 `bookshop_window` 的同一个原创动漫店员。一次制作得到的立绘、角色包、手机录屏和会话记录可以支持六项判定。人物特点、参与者或动作脚本换了，重新登记场景组。

| 检查点 | 要回答的问题 | 最有区分力的证据 |
| --- | --- | --- |
| BW01 创作 | 第一次制作的用户能否自己走到 App 安装并打开角色？ | 完整操作录屏、发布清单与打开事件。登记人工代操作、重试与放弃。 |
| BW02 外观 | 蓝色书签胸针佩戴在哪一侧？ | 带人体左右标注的参考立绘及相同视角的中性画面。 |
| BW03 动作 | 待机循环的接点是否跳动？ | 连续三轮原始录屏、接点时间戳及鼻尖标注。按脸宽归一化位移。 |
| BW04 性格 | 三次独立对话中，设定为“先了解顾客”的店员是否先问再推荐？ | 同一版本的角色卡和三份完整回复，标出首次提问及首次具体推荐。 |
| BW05 记忆 | 重新登录后能否想起上次约定的随机取书暗号？ | 首次写入回执、新会话和实际答复。暗号不能出现在新会话提示里。 |
| BW06 打断 | 打断后旧回复是否仍从扬声器播出？ | 设备最终音轨、播放停止事件及统一时钟。界面图标变化仅能说明界面状态。 |

生产角色另设隔离、删除后重建等硬项。出现串用户记忆或已删事实重新可检索，应阻止发布。关键项无证据时先补测；其他方面的高分不能抵消该缺口。静态外观和部分预渲染视频可以跨路线比较；3D 交付、实时打断及动态口型另设资格线。H3 的短片可进入同任务的视觉评测，不能凭短片成绩获得可驱动角色资格。

## 用 2×2 实验定位收益

首个实验选择同一项任务：根据参考立绘，从同一套 3D 部件库推荐发型、服装、配饰和颜色。身份特征节点开启时，只额外提供预先规定的结构化特征，例如“角色左胸有蓝色书签”。这些特征由冻结的提取器读取原图产生；人工答案、评审标注和测试标签不能作为生成输入。外观主指标预先指定，打断、记忆等用例作为发布回归项独立报告。

| 运行 | 部件推荐模型 | 身份特征节点 | 可以做的配对比较 |
| --- | --- | --- | --- |
| A0 | A | 关闭 | 基线 |
| A1 | A | 开启 | A1 与 A0 显示该节点在模型 A 上的边际效果 |
| B0 | B | 关闭 | B0 与 A0 显示关闭该节点时，换模型的效果 |
| B1 | B | 开启 | B1 与 B0 显示该节点在模型 B 上的边际效果 |

如果 A 得益而 B 变差，再检查两种模型对同一组结构化特征的利用方式。交互差按 **(B1 − B0) − (A1 − A0)** 计算，各差使用同一指标。每个检查点有四份有效证据才参与完整配对；按角色或场景先汇总，再对完整组等权。另报所有尝试的通过数、弃权、失败和缺失，避免仅凭幸存样本选方案。对每个模型记录采样参数、种子支持情况；供应商不能复现随机种子时使用同一输入做重复采样并披露。产品比较需要相同重试与人工修复预算。

`plans.json` 是未执行的实验计划，内含素材、母版、目录、动作、审核配置及重试策略的占位版本。正式运行前将它们换成不可变 ID 或内容哈希。每次运行保留实际执行的图、节点和模型版本、输入及输出哈希、推理种子（如可用）、每次尝试的耗时和费用、人工用时、设备和播放器版本。计划检查验证声明中的变量；实际执行过哪些节点，要用运行日志核对。

另两项值得单独做的消融是 **最近几轮历史 / 加入长期记忆召回**，以及 **角色卡 / 同一张角色卡加示例对话**。分别看跨会话记住、更正、遗忘和隔离，以及语气、边界、动作是否符合人设。每轮只改一项，冻结其余模块。不要用同一模型同时更换生成和审核两个角色来做效果归因。

## 如何判断审核员可信

1. 从相同素材制作“正确、已知缺陷、边界模糊、缺证据”四类产物。缺陷可控地加入，例如胸针换侧、循环末帧跳变、旧记忆回写。真实失败案例也要保留，尤其是外观漂亮但运行行为错误的角色。
2. 两位人审独立盲评同一份完整证据，再由第三人裁决分歧。记录原始分歧和裁决理由。人为构造的已知答案可以检验工具；真实风格偏好需人审金标。明确需要日志或连续音视频的检查，不用静态截图代替。
3. 固定审核模型、提示、媒体采样设置和判据。分维度报告错放率（人工判失败，AI 判通过）、错杀率（人工判通过，AI 判失败）、AI 有效覆盖和弃权。分母分别列出，硬项逐例展示。两边模型名称隐藏。如补做成对偏好，再交换左右位置重评，保留顺序敏感的样本。
4. 每次改审核员，用固定候选与固定人审金标重新校准。每次改候选流程，用冻结的审核员重新打分。角色原画、同一视频的帧、同一段对话的改写保持在同一个数据集。最终由未参与调参的人保管独立角色与场景的私有留出集，避免边看结果边改题。
5. 按每个合格角色的总推理费用、人工返修时间、一次通过率及硬项表现决策。小样本先看逐例胜负和失败录像。补足独立角色后，以角色为单位做配对置信区间，并单列平台、画风和设备差异。同一角色的帧数、轮次或随机种子均不能计作独立角色数量。

视频评测的主体一致性和时序维度可参照 VBench。记忆更新、跨会话推理和未知时不作答可参照 LongMemEval 的题型。LLM 评审的位置偏差可参考 MT-Bench 作者的实验。本项目的检查点及合格线需要机构自行验证。[VBench](https://github.com/Vchitect/VBench) · [LongMemEval](https://github.com/xiaowu0162/LongMemEval) · [MT-Bench 与评审偏差](https://arxiv.org/abs/2306.05685)

## 本地运行

Python 3.9 或以上。文本和图片路径使用标准库；提交视频需系统提供 ffprobe。以下命令在本目录执行。前四条均离线，`prepare` 写入的新路径须尚不存在。

```sh
python3 bench.py validate
python3 ablate.py check A0 A1
python3 review.py prepare examples/visual-correct.jsonl --run-id fixture-Z4 --model preview --out prepared.jsonl
python3 bench.py compare examples/smoke-swapped.jsonl examples/smoke-correct.jsonl --split dev
```

最后一条会显示 BW02 一次可比配对，其余 13 个开发集检查点缺少本次证据。可比的一项发生改善，开发集整体尚未完成。

**接入已有审核模型。** 为每次运行制作一份证据 JSONL。每行 `id` 对应用例，`items` 中每项提供所需 `key`、匿名定位 `ref`，以及 `text`、`image`（PNG/JPEG）或 `video`（MP4）之一。图片与视频相对 JSONL 所在目录。可以为同一键提供多份材料，每个 ref 唯一。正确的结果定位是 `ref原文｜观察`。看到缺失键直接弃权；提供错误介质会报输入错误。审核员不会收到输入文件名、运行编号或计划中定义的模型名称；提供方仍要清除证据文本和水印中的标识。

`run` 才向显式选定的端点传送证据。端点须兼容 Chat Completions 格式，并支持所需输入。密钥可通过 `BENCH_JUDGE_KEY` 环境变量提供。图片模式是默认值；兼容 `video_url` 且经过验证的端点可用 `--media video`，能同时理解音轨的端点可用 `--media audiovideo`。客户端核验文件流及媒体类型；审核端点的抽帧密度或音轨能力需要先用已知缺陷样本验证。连续帧级指标应以可复算的测量日志为准。私有对话和机构素材仅发给具备相应授权的端点。

```sh
python3 review.py run evidence.jsonl --run-id trial-01 --model "$BENCH_JUDGE_MODEL" --endpoint "$BENCH_JUDGE_ENDPOINT" --out judged.jsonl
python3 bench.py calibrate human-gold.jsonl judged.jsonl --split dev
python3 bench.py compare baseline.jsonl candidate.jsonl --split dev
python3 ablate.py interaction A0.jsonl A1.jsonl B0.jsonl B1.jsonl --split dev
```

`run` 逐条落盘。服务中断后，用原命令附加 `--resume` 可续跑。证据、用例、审核器配置或运行编号改变时需另开结果文件。人工结果使用 [审核协议](judge.md) 里的 JSONL 结构，建议从 `prepare` 结果复制相应的 `id`、`run_id`、`case_sha256`、`evidence_sha256`，让工具核对金标与 AI 是否针对同一个产物。对图像和日志的真实观测仍需按 ref 复查。

完整的私有人审金标、机构素材、真实 3D 角色包、H3 生成结果、真机录屏和多模型费用尚待采集。本次合成试跑无法估计真实角色的通过率，也无法选出最优工作流。
