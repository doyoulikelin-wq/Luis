# 端到端消融与审核员校准

每个候选从原始素材走到同一目标：在播放器打开角色，按指定事件脚本完成动作或对话，并保存失败、放弃和修复成本。中间指标用于定位问题。更换整个模型或工作流产生的差异只支持比较整套方案；归因到单个节点需要配对消融。

## 实验登记与执行

1. 先定义本轮决策、主指标、允许退化幅度、硬性失败项和目标用户群。按角色/素材来源划分开发与私有留出集，同源动作片段、帧和随机种子留在同组。仓库两份公开题库中的 holdout 仅供流程预演。
2. 锁定原图和动作母片的授权、SHA-256、母版/骨架和独立标定、模型及权重、提示、节点图、相机和渲染、设备、评审员、重试与人工预算。记录每个节点的输入/输出哈希、时间和失败类型。私有素材与人审记录留在机构存储。
3. 把 [单变量计划](pipeline-plan.json) 的占位符替换为不可变版本。用以下命令检查两组声明只有一项不同。另用实际节点日志核实开关生效。未实现的模型或节点是待验证假设。
4. 对同一组素材分别跑开/关，封存产物后再送匿名评审。跟踪创建成功、有效记忆/正确性格、可播放动作、单位合格角色成本与人工返修。另量化审核员有效覆盖、错放和错杀。逐组列出失败/弃权，报固定总分母与完整配对分母。
5. 单变量效应可随模型、角色体型和动作改变。优先将可疑因素组合成 2×2，例如模型 × 特征提取、骨长修正 × 端点重连。固定其他设置并计算两组差之差。部署选择由未参与调参的不同角色、真机和独立评审复核。

```sh
python3 benchmark/ablate.py check full no_recall --plan benchmark/experiments/pipeline-plan.json
python3 benchmark/ablate.py check A0 A1 --plan benchmark/plans.json
```

| 阶段 | 一次只改变 | 主观测与应守住的回归项 |
| --- | --- | --- |
| 素材和创作指导 | 保留/移除身份特征提取；另轮比较补图和纠错指导 | 眼镜、胸针、左右身份、独立安装、流失、技术人员工时 |
| 绑定、重定向和修整 | 长度约束、亲子重连、扭转分摊分别开关 | 骨长误差、间隙、带符号局部角、蒙皮网格及故障是否转移到邻骨 |
| 调度和呈现 | 转场混合、缺动作回退分别开关 | 接缝速度、手势意图、过期事件、打断尾音、实际设备呈现时钟 |
| 角色包和发布 | 预检开关，输入同一批已知好包和坏包 | 错误放行、正确拦截、误拒、可安装、损坏回退；分母包括所有入队产物 |
| 性格和私人记忆 | 固定底模，移除示例对话、长期召回、遗忘标记，各做一轮 | 跨会话、更正、遗忘、故意未知、身份隔离、人格边界；硬项失败单列 |
| 端到端交付 | 先比较完整方案，再做上述逐项消融 | 总尝试数、自动完成、人工修复、放弃、每个合格角色耗时/费用 |
| 审核器本身 | 冻结同一批候选，只换评分器/提示/取证方式 | 对同份金标算错放、错杀与弃权；与生成节点的改动分别测试 |

共享角色和多个随机种子构成重复测量。按角色先汇总，再算配对差和角色级置信区间。只有一个假人时报告逐动作原值；不能把几千个相邻帧计作几千个独立样本。比较交互较多的创作向导时，记录学习效应。一次只动分离良好的节点；移除节点导致下游输入缺失时，用已定义的直通代替并保留相同输出契约。不同输出介质只比较各自能观测的结果，另列动画能力和发布资格。

## 什么时候可以信任评审

组织两位评审独立标注已知缺陷、真实失败、正常风格化、遮挡/缺证据四类样本；记录一致率、分歧和复核结果。AI 与程序分别接受同一组正负/无证据测试。错放率以人工确认的失败样本为分母，错杀率以人工确认的合格样本为分母，弃权率以全部送审样本为分母。严重断肢、隐私串用和已删记忆复活任一出现均单独处理。避免把 0 次错放解释成真实错放率为 0；例如在独立同分布的失败样本中要使单侧 95% 二项上限低于 1%，零错放也至少需要 299 个失败样本。这个数字说明样本量与声明的关系；部署阈值应由团队预登记。

## 开源方法来源

- Inspect AI 把任务定义、受测系统、评分器和运行日志拆开。这里借鉴其可替换评分器与逐样本证据设计。[Inspect AI](https://github.com/UKGovernmentBEIS/inspect_ai)
- VBench 将主体一致性、时序闪烁和动作顺滑度分项评价。这里进一步检查骨架、蒙皮与窗口接触，避免视觉顺滑掩盖肢体错误。[VBench](https://github.com/Vchitect/VBench)
- Khronos 的 glTF Validator 可检查资产结构与规范问题，VRM/VRMA 定义人形骨骼和动作交换语义。最终角色形变还要检查蒙皮后画面与运动轨迹。[glTF Validator](https://github.com/KhronosGroup/glTF-Validator) · [VRM Animation](https://vrm.dev/en/vrma/)
- LongMemEval 的跨会话检索、知识更新、未知时不作答适合检验长期记忆收益。机构间隔离和删除后重建是本项目另加的验收项。[LongMemEval](https://github.com/xiaowu0162/LongMemEval)

## 已运行的骨长约束与端点重连实验

使用网页同一个动作生成器、一个冻结骨架、三段动作。给同一输入同时注入可控的前臂延展与肘部脱节，再对长度约束、端点重连分别开关。独立文件固定静止长度、父子关系和阈值，四个候选均使用同一离线测量器。建议检查失败位置是否转移到邻骨、手势意图和蒙皮是否受到损害。

| 长度约束 | 端点重连 | 最大骨长相对误差 | 最大连接间隙 |
| --- | --- | ---: | ---: |
| 关 | 关 | 58% | 91.79 mm |
| 开 | 关 | 浮点精度内为 0 | 91.79 mm |
| 关 | 开 | 58% | 浮点精度内为 0 |
| 开 | 开 | 浮点精度内为 0 | 浮点精度内为 0 |

三个动作各自呈现同一模式。输入为同一个程序化假人的相关动作；约束指标按构造得到满足，不推导出真实人体动作更自然。干净负对照、输入指纹、阈值和逐动作结果见[实测记录](repair-results.json)与[冻结标定](rig-profile.json)。下列命令从仓库根目录执行，需要 Python 3.9+ 与 Node 22.12+。导出的轨迹可在网页的「导入轨迹」中选择并回放。

```sh
python3 benchmark/experiments/repair_ablation.py
python3 benchmark/experiments/repair_ablation.py --export wave both /tmp/luis-wave-repaired.json
python3 benchmark/motion.py /tmp/luis-wave-repaired.json --profile benchmark/experiments/rig-profile.json
```

## 网页角色从制作到回放的四组实验

实际网页使用同一母版、衣服颜色、场景脚本和动作播放器。组合两种人格（沉静、开朗）和两种记忆授权（关、开），每组使用全新的浏览器上下文。脚本在界面设置角色、导出公开角色包、导入成新实例，通过相同场景读取台词并导出动作轨迹，经刷新后核对称呼、纠正、遗忘和实例隔离。关闭授权组以“不保存”作为正确结果，保留授权组以“能正确记住、更正、忘记”作为正确结果。两种策略的通过条件不同。

此实验使用社区工具 [Playwright](https://github.com/microsoft/playwright) 驱动本地网页；网页本身不依赖 Playwright。需要 Node 22.12+、Python 3.9+ 和可用 WebGL 的 Chromium。先启动仓库静态服务，再在下方命令中使用已安装的 Playwright。工具支持 `LUIS_PLAYWRIGHT_MODULE`（模块路径）、`LUIS_CHROME_PATH`（可执行文件）和 `LUIS_WEB_URL`（默认本机 8774 端口）。如使用本地安装的 Playwright 及其 Chromium，直接运行即可。

```sh
node benchmark/experiments/web_flow.mjs
```

执行结果见[四组浏览器记录](web-flow-results.json)。它检验已实现的本机脚本、角色包和动作链路；外部模型的人格稳定性、线上记忆和原生 iOS 设备仍应使用独立实验。
