# 触摸失活与恢复 benchmark

这套测试问三个问题。手指仍在移动时，角色是否还响应新意图？手指松开或被系统打断后，旧动作是否退出？下一根手指能否在当前页面重新取得控制，并让屏幕产生对应变化？三项分别给出证据。一次手势方向判错、需要抬起再按、后续输入也被阻塞，是三种不同严重程度。

## Chromium 如何确认恢复

1. 记录环境、角色资产指纹、浏览器事件和命中元素。记录触点编号、主次标记、事件生成与送达时间。在用例内确认实际触发预期的中断，例如出现滚动、指针取消或页面缓存恢复信号。
2. 保持用例留下的页面和控制器，在左侧用一根新指按住，拖至右侧，折返左侧再松开。每个场景独立建浏览器上下文；同一场景内的故障与恢复探针连续执行。用例需要刷新或返回时，探针落在用户实际返回的页面。
3. 对齐同一根新指的按下与抬起、控制器受理、跟随方向、结束与回正。在左右状态分别截取用户可见的小窗画面，比较左→右、右→左的差异与左→左的重复噪声。只有状态字段变化而三张屏幕完全相同时单列显示冻结。图像无法可靠区分时记未验证。
4. 保留四组校准。正常版本应通过。透明遮挡层应被定位为命中失败，事件仍命中角色却被监听器拦截时应检出控制失败，固定画面覆盖在仍运转的角色上时应检出显示失败。脚本请求位置与浏览器实际送达位置偏差超过 2 CSS px 时，将恢复探针记为坐标未验证。校准通过表示观察器识别出了预期结果。

用例包含三种判据。**既有契约**覆盖已承诺的单指交互。**候选产品策略**用于暴露体验差异，例如窗外已有一指时，窗内第一根手指能否接管；是否采纳可独立决定。**故障注入**刻意压住事件或制造特定时序，用于比较实现的恢复能力。通过、失败、未验证、执行错误分别计数。样本为定向挑战用例，不能用失败项比例估算真实用户的发生率。

当前画面比较在 80 × 64 的采样网格上计算 RGB 通道平均绝对差。两次跨侧差异均须大于 0.8 且超过同侧差异的 1.6 倍。该参数和左右姿态的准备条件由此版本标定。接受、跟踪、释放及回正的等待预算分别为 1250、900、1100、1500 ms，包含测试所需的 350 ms 长按。它们用于限定何时停止等候。报告里的 downToAckMs 测量事件送达到同步受理，releaseToIdleFrameMs 测量送达到观测到空闲帧；eventSpanMs 包含脚本主动保持和截图的时间。手指接触至物理屏幕发光的时间需要外部采集。

默认 JSON 保存截图哈希与比较距离。用 `--frames /tmp/luis-probe-frames` 可在复跑时保留左右探针达到采样条件时的原始 PNG，供人工或其他评测器复核。

浏览器用例的 native-touch 指 DevTools 送入浏览器输入栈后产生的可信 DOM 事件。mixed 组合了浏览器输入与受控条件，injected 含脚本构造的事件。iOS 模拟器单独报告，它的 Safari 生命周期及角色事件回放各自注明证据等级。

## 本地复现

在仓库根目录启动静态服务。

```sh
python3 -m http.server 8774 --bind 127.0.0.1
```

另开终端，仍从仓库根目录执行。测试依赖装在临时目录。可用 LUIS_CHROME_PATH 指定已有的 Chrome 可执行文件。

```sh
tools_dir="$(mktemp -d)"
npm install --prefix "$tools_dir" playwright@1.62.1 pngjs@7.0.0
export LUIS_PLAYWRIGHT_MODULE="$tools_dir/node_modules/playwright"
"$tools_dir/node_modules/.bin/playwright" install chromium
node benchmark/touch/run.mjs --list
node benchmark/touch/run.mjs --repeat 2 --out /tmp/luis-touch.json
node benchmark/touch/run.mjs --case missing-up-and-capture-loss --out /tmp/luis-terminal.json
```

可通过 LUIS_WINDOW_URL 切到线上预览，或用 `--suite calibration,contacts,terminals` 选组。命令在所有判据符合预期时返回 0，观察到失败或证据不足时返回 1，执行器异常时返回 2。JSON 含单例断言、输入片段、关键模式、配对参数、恢复探针与资产 SHA-256。

在已启用 Safari 自动化、安装并启动 iOS 模拟器的 Mac 上，可补跑 Safari。下列命令中的 SIMULATOR_UDID 指向自己的已启动模拟器；background 会在模拟器里切到设置再回到 Safari。其 App 切换用例从同一 checkout 提供角色页面并追加观测脚本，其他行使用指定 URL。

```sh
python3 benchmark/touch/safari_smoke.py --udid "$SIMULATOR_UDID" --background --out /tmp/luis-safari.json
```

若要确定故障发生后实际需要多少干预，可运行单独的恢复阶梯。同一现场按顺序尝试两次新接触、切换标签再回来、重新加载。每步重复控制和显示探针，保留最小成功干预。

```sh
node benchmark/touch/recovery-ladder.mjs --repeat 2 --out /tmp/luis-recovery.json
```

## 用于视频、序列帧及骨骼方案的消融

固定同一输入轨迹、初始状态、视口、冷/热缓存与中断时刻。每次只替换一项，例如松手清理、触点接管规则或视频打断调度。不同实现都要交付“新触点 → 受理 → 生效的动作 → 用户实际看到 → 退出”的证据。视频登记实际呈现的分支和时间，序列帧登记实际绘制的帧，骨骼登记已应用的姿态。连续拖拽的目标镜像轨迹共用，输出可以选头部转向、手移动或其他易区分的响应。

当前实现的页面观测接入在 harness.mjs，定稿角色的受理、左右目标与回正条件集中在 window-adapter.mjs。接入新渲染器时需映射对应状态，并先用该方案的正常交互、透明遮挡、吞输入和冻结输出四组样本校准。左右状态下可见画面能否区分是一个独立检查。三次取样不能单独排除自主动画恰好变化，也不能确认实际运动部位或镜像方向。动作自然度、关节正确性另由动作专项评审。候选实现用逐例配对结果比较，保留所有失控和未验证项。
