# 缓存返回及拖拽松手修复

播放器 [版本 ba19f97](https://github.com/doyoulikelin-wq/Luis/tree/ba19f97c91cdb0aaf2f449f5b91497539856b1de/platform/web/window) 默认启用两项修复。修复前的播放器和原版评测封存在 [touch-baseline-dbb9a15](https://github.com/doyoulikelin-wq/Luis/tree/touch-baseline-dbb9a15)。[手机预览](https://doyoulikelin-wq.github.io/Luis/platform/web/window/?v=touch-recovery-1)

## 两项修复如何生效

- **A · 页面返回。** 缓存离开、重新显示各清理一次旧接触。若浏览器恢复后仍将新指报告为非主触点，播放器跟踪返回后在整页真正按下的手指，只让第一根独立的窗内新指接管。两根同时按住时保留已有所有者；浏览器再次报告主触点后，恢复常规判定。
- **B · 拖拽释放。** 正常抬手与取消沿用现有识别。丢失通知时，根据浏览器持有的指针捕获状态、可信触摸结束和新的独立触点确认旧接触何时结束。针对静止不动的手指不设超时。返回后的触点编号按各自的事件体系追踪，可排除离页前滞留的触点。

## 配对消融

每格为通过次数 / 执行次数，两轮均在新的浏览器上下文开始，故障和后续探针则在同一现场连续执行。历史基线逐文件来自 Git；双关、仅 A、仅 B 的临时副本只在初始化时传入对应开关；A+B 使用实际发布入口。所有候选的交互模块指纹相同，未改造评测阈值。Chromium 158.0.8127.37，视口 390 × 844 CSS px。公开预览使用 A+B。

| --- | ---: | ---: | ---: | ---: | ---: |
| 先抬手再离页，缓存返回 | 2/2 | 2/2 | 2/2 | 2/2 | 2/2 |
| 持按离页，在外页发出松手后返回 | 0/2 | 0/2 | 2/2 | 0/2 | 2/2 |
| 单独送达缓存离开与恢复，省略释放通知 | 0/2 | 0/2 | 2/2 | 0/2 | 2/2 |
| 只截断 pointerup | 2/2 | 2/2 | 2/2 | 2/2 | 2/2 |
| 同时截断松手与失去捕获，新指再次操作 | 0/2 | 0/2 | 0/2 | 2/2 | 2/2 |
| 双终止缺失，松手后静候，无新输入 | 0/2 | 0/2 | 0/2 | 2/2 | 2/2 |

双终止缺失后的安静观察不发送任何第二触点。两轮均在 500 ms 窗口内观察到退出，可信松手送达至首次空闲帧分别为 16、16 ms。这是浏览器内观测。恢复阶梯另在两个原故障上各做两轮，每次均由第一根新指接管，并通过左右折返、可见画面及松手回正检查。旧版对应的最小成功干预分别是切换标签和刷新页面。[本次恢复阶梯](recovery-ladder.json.gz) · [基线恢复阶梯](../recovery-ladder.json)
