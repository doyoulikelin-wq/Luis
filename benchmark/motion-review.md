# 上半身角色动作验收

在 App 中做一次“挥手”，至少要回答三个独立的问题。骨架在重定向后是否连续？皮肤、袖口、手指在最终画面里是否完整？动作有没有在正确的话语和手势提示处发生？`motion.py` 负责第一个问题中的六项可测量指标。输出中的通过只覆盖声明的骨、关节、采样窗口与阈值。将轨迹报告与同一运行的画面、事件记录并排审核，分别报告结论。

## 运行

在仓库根目录执行。网页动作诊断导出的 JSON 可以直接作为输入。Python 标准库即可运行；默认写到标准输出，`--out` 写入新文件。

```sh
python3 benchmark/motion.py trace.json
python3 benchmark/motion.py trace.json --profile frozen-rig-profile.json --out report.json
python3 -B benchmark/test_motion.py
```

命令正常完成时返回 0，报告中的 `verdict` 区分 `pass`、`fail`、`abstain`。命令返回 2 表示输入协议、配置或文件操作失败。每项报告给出单位、有效观测数、缺测数、超限数和最接近或超出约束最远的观测 `worst`。其 `target` 定位骨或关节，`frame` 从 0 计数，`t_start/t_end` 使用秒。任何一处有充分证据的几何或运动越界均保留为失败；其余缺测保留在同一报告中。只有采样间隔超限时，时钟检查失败，动作总判为弃权。补齐轨迹后重跑。

### 轨迹与标定

`schema` 固定为 `luis.motion-trace.v1`。`units` 为 `m`，`space` 为 `avatar_local`，表示所有骨都转换到同一角色坐标系，已经包含父级变换；不要把各骨自身局部坐标、像素或不同相机的坐标混合。每个采样带实际 `t`（秒）；`fps` 是约定的均匀采样率。按模型的实际左右命名。生产采样应位于 IK、动作混合与重定向之后，分别保留动作源、目标骨架、最终渲染的运行与时间关联。[Khronos glTF 2.0 规范](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc) · [VRM Animation 及重定向说明](https://vrm.dev/en/vrma/)

下面是**模拟两骨段样例**，单位为米。每段的 `head` 和 `tail` 是该骨本地分别定义的近、远端标记，经**该段自身的最终变换**映射到共同空间。父骨远端、子骨近端各算一次。在共用一个“肘关节点”填两个位置的数据中，间距会恒为零。此时 `anchors` 应填 `shared_joint_samples`；来源不清楚填 `unknown`。这两种情形以及未提供声明，连接检查均弃权。

```json
{
  "schema": "luis.motion-trace.v1", "units": "m", "space": "avatar_local",
  "anchors": "independent_segment_markers", "connection_default":"coincident", "fps": 30, "action": "demo", "fault": "none",
  "bones": [{"id":"arm","parent":null,"rest_length":0.30},{"id":"forearm","parent":"arm","rest_length":0.25}],
  "joints": [{"id":"elbow","parent":"arm","child":"forearm","angle_deg":[0,150]}],
  "frames": [
    {"t":0.0,"bones":{"arm":{"head":[0,0,0],"tail":[0.30,0,0]},"forearm":{"head":[0.30,0,0],"tail":[0.55,0,0]}}},
    {"t":0.0333333,"bones":{"arm":{"head":[0,0,0],"tail":[0.30,0,0]},"forearm":{"head":[0.30,0,0],"tail":[0.55,0,0]}}}
  ]
}
```

冻结配置是**独立测量与经审核的约束**。以下示意与上述两骨样例对应。正式测试先从受信任的绑定姿势、仪器标定或单独基准测量取得 `rest_length`，确认标记确实各自变换；再由动画负责人按角色比例、动作、风格及目标设备核定阈值。令两个候选使用同一预登记配置。不要从候选首帧倒算基准长度；如果第一帧已拉伸，后面每帧都会被错误地接受。没有额外发布证据时，导出器自报的“独立”也只是采集方的声明。

```json
{
  "anchors":"independent_segment_markers", "connection_default":"coincident", "fps":30, "window_s":[0,0.0333333],
  "bones":[{"id":"arm","parent":null,"rest_length":0.30},{"id":"forearm","parent":"arm","rest_length":0.25}],
  "joints":[{"id":"elbow","parent":"arm","child":"forearm","angle_deg":[0,150]}],
  "limits":{"length_rel":0.05,"gap_m":0.01,"angular_speed_deg_s":720,"endpoint_speed_m_s":6,"max_frame_dt_s":0.08}
}
```

这里的数字只用于演示。传入 `--profile` 后，工具仅使用独立配置的骨表、静止长度、角度、帧率和五项阈值。外部配置缺数值阈值时报配置错误，缺必要关节、骨或正标定长度会使相应检查弃权。连接通过还要求配置和轨迹均声明独立端点。顶层 `window_s` 可约定预期首尾；缺少该字段时输出范围仅限已提交样本，无法发现被截去的整段开头或结尾。未指定独立配置时报告标记 `self_reported_demo`，阈值可使用演示默认值。外部配置标记 `external_profile`。随报告保存 `trace_sha256`、`profile_sha256`、导出器版本、模型包/动作版本和运行号。哈希能核对文件一致性，标记来源的可信度仍需独立确认。

### 绑定层级与应测连接

`parent` 仅用于描述变换层级。冻结配置在每个非根骨段的 `connection` 中声明实际测量对象，优先于 `connection_default`。两种来源不能混用；启用外部配置后，轨迹自报的默认连接类型或附件名不能填补冻结配置的空白。

| 子骨的配置 | 实际观测与结果 |
| --- | --- |
| `{"kind":"coincident"}` | 父骨远端应与子骨近端重合。量两枚独立标记在每帧的距离。 |
| `{"kind":"offset_socket","parent_socket":"sleeve_mount"}` | 子骨绑定在父骨的另一个附件位。按该帧父骨最终变换导出 `frames[i].bones[parent].sockets.sleeve_mount` 三维位置，与子骨 `head` 比较，这条连接可以与父骨 `tail` 相距数厘米。缺命名附件、缺该帧附件位置或只有绑定姿势偏移量时，连接弃权。 |
| `{"kind":"unobserved"}` 或缺少该边声明且无全局约定 | 连接几何没有足够观测或不适用于这条边。报告按骨名列缺口，保留其余可观察连接的测量；整组连接和总报告不会因此得到全通过。 |

只有在逐边确认几何约定相同的受控骨架上，才设置顶层 `connection_default:"coincident"`。Luis 演示假人及其独立配置使用这一约定，服装、道具、辅助骨和带偏移的肩部常需单独声明。父端的附件位置须从父骨自身变换取得；复制子骨近端坐标会隐去真正的分离。

## 六项自动检查

| 检查项 | 算法与失败定位 | 可观测边界 |
| --- | --- | --- |
| `bone_length` 骨长变化 | 每一帧量近、远端间距，求其相对绑定长度的偏差绝对值；骨段、时间、偏差比例随结果输出。 | 能检出整体恒定拉长或缩短。两截手臂整段错开时，各自长度仍可正常。 |
| `joint_gap` 父子分离 | 按所声明的每条边，用父段远端或已变换的父骨指定附件位与子骨近端比较米制距离。 | 根节点没有父端。未标定或无法观察的附件单独保留缺口。骨架相接仍可能出现蒙皮裂口。 |
| `joint_flexion` 肘部屈曲 | 计算两段近端指向远端的向量夹角，直臂为 0°；逐关节比较已冻结范围。零长度或缺点弃权。 | 只测 0–180° 无符号角。反向折肘可能与正常屈肘同角，绕骨轴的扭转也保持端点不动。判断方向需局部关节基、旋转或额外离轴标记，并由第二视角确认。 |
| `endpoint_speed` 端点突跳 | 相邻有效帧同一端点的位移除实际时间差，输出米/秒，给出跨越的两帧时间。 | 相同的快动作可能是合理甩手；阈值须按角色、动作及部位标定。根运动、镜头移动不应混入角色局部速度。 |
| `angular_speed` 屈曲突跳 | 相邻有效帧同一关节的屈曲角之差绝对值除时间差，输出度/秒。 | 能发现单帧折角突变。肩部带动整条直臂时屈曲速度可以是零；恒速僵硬、低幅颤动、沿轴翻转等仍需画面、局部旋转或更高阶轨迹分析。 |
| `sample_interval` 观测缺口 | 不排序原始数据。时间须递增；有效间隔上限为配置值与名义帧周期 1.5 倍中较小者。跳过超限区间的速度计算，保留可定位的时间缺口。 | 只说明所报采样时钟；匀速离线重采样无法追溯先前被丢弃的真实帧。App 或视频播放器实际掉帧，应同时取呈现时刻、解码/丢帧计数及帧时间线。 |

轨迹中存在一次实测越界即可提交该时间段的诊断证据。有个别帧缺点时，缺点相关的检查不得给通过。对于相邻关节使用同一位置或从 2D 图像估算深度的任务，人工可记录“画面上看见裂缝”，同时保持“3D 连接几何”未判。浏览器视频播放质量规范将实际显示或丢弃的帧单独计数，可用于区分播放问题与源动作问题。[W3C Media Playback Quality](https://w3c.github.io/media-playback-quality/)

报告的 `intervals` 列出已提交帧的相邻间隔数、通过时间检查的间隔数和跳过数。例如八帧中删去一帧后，余下七帧有六个相邻间隔，其中一处跨缺口，可用于速度的只有五处；端点速度和屈曲角速度都不计算跨缺口的差商。若其余区间未超限，相应速度项与总报告均弃权。如果另一对完整相邻帧已有实测超限，保留此处失败和缺帧原因。`missing` 统计缺测和阻止通过的缺口标记，不等同于丢帧数。

## 最终画面与交互验收

| 层面 | 采什么、怎样对照 | 判定与取证 |
| --- | --- | --- |
| 蒙皮和形体 | 正面和侧面录屏，配同帧骨架叠加；屈肘、举手、身体转向各取动作峰值前后片段。 | 记录肘窝塌陷、旋拧、肩缝、关节断裂、穿过躯干或道具；区别肢体被袖口遮住和皮肤表面真实分开。转视角后仍缺乏证据则弃权。 |
| 手、脸、头发及布料 | 手指展开/握拳/遮脸，逐帧检查指尖数量、掌指相连、左右手、面部覆盖次序；观察袖口、头发、饰件与肩或身体相交。 | 本工具示例骨架没有逐指、面部、布料或碰撞数据。对实际可见的多指、粘连、穿模、抖动、轮廓破碎分别定位。不可见的手指不得推定丢失。必要时补网格碰撞或深度缓冲。 |
| 运动目标与节奏 | 预先标记驱动表演中开始、最高点、两次换向和回到待机的窗口。对齐驱动与生成录屏，记录手腕方向、距离、动作是否做全、停止后是否漂移。 | 恒定站姿也可以通过六项几何约束。验证“挥手”必须另查语义轨迹；同样，风格化角色刻意拉伸或预备动作可按事先批准的角色配置验收。保留异常画面供创作人员决定。 |
| 时间连续与切换 | 保存整段视频、单帧时间码、输入触发与动作状态时间线；多次重播循环接缝、首/末姿态、打断与回待机。涉及嘴形时再保留设备实际音轨。 | 查单帧跳变、突然反向、根漂移、身体僵住、循环接缝、音画错位。区分内容重复帧、屏幕录制丢帧及播放器丢帧。离散截图只能支持截图时刻的判断。 |
| 输入与输出坐标 | 核对原素材的镜像、帧率、缩放、人物朝向、相机视角、骨骼映射和附件范围。相同相机运动时用相机基准消除镜头效应。 | 镜面左右、透视缩短、视角切换及裙袖遮挡都可能造成假断肢。单视角深度不确定时，补同步侧面或可信模型空间轨迹。 |

## 对照、盲评与发布判据

**把动作环节纳入整条链的消融。** 固定输入素材、源动作、角色骨架、相机、设备、种子、测试用例和独立审核配置。每次只改变生成链的一个指定组件，给开关两侧不同运行号。记录各阶段产物，避免仅从末端一个分数猜测故障来源。下面是可执行的对照设计，具体生成器和设备接入后才会产生真实结果。

| 消融项目 | 同组固定的证据 | 读取的成对变化 |
| --- | --- | --- |
| 参考图归一化开/关 | 原图、尺寸、镜像标注、同一驱动和发布设置 | 身体左右、腕部峰值裁出比例；结合两边裁切、归一化结果定位原因。 |
| 骨骼映射或 IK 校正开/关 | 同一输入姿态、绑定骨长、关节角配置 | 动作源、求解后与 App 三处轨迹分别审；检出越界或分离首次出现的阶段。 |
| 时序平滑开/关 | 相同源表演与采样时钟，独立标记的手势起点/换向窗 | 同时报峰值速度、运动窗口偏移和画面复核；平滑可降低突跳，也可能延迟挥手。 |
| App 动作过渡开/关 | 同版动作文件、两种动作的切换事件和目标设备 | 比较切换边界附近的腕部轨迹、响应延迟与最终画面。 |
| 评审证据拿掉一类 | 不变的动作与判据，分别移除独立端点、侧视图或连续时钟 | 应出现对应弃权；如果仍给几何连接、遮挡后深度或整段流畅度通过，说明评审器错误放行。 |

同一摄像机或两个模块一起改动时，另设独立单项对照和同时开启的组合，才能检查交互效应。跨素材、动作和种子重复；少量精选演示、故障注入或观察到相关性均不足以计算单个生成模块的真实收益。

1. 先冻结角色、绑定标记、设备、动作描述、风格允许范围、视频时间窗口和阈值。用开发集的合格动作、边界动作和被动画师确认的问题动作标定。写明每项允许的幅度和持续时间；当前工具按单次越界报事件，连续帧同一问题在人工汇总时作为一个事件。
2. 使用相同输入、动作、相机和设备比较两个候选。保留动作源和渲染成片，盲审包隐藏品牌、候选号含义、故障标签、文件名中的答案，以及会泄漏答案的叠字。独立保留原始输入与哈希。工具忽略 `fault`，判定依赖坐标和阈值。
3. 人审先独立提交“通过/失败/弃权”和文件、时间段、可观察现象。两位评审对遮挡、夸张动作或接缝有分歧时，由第三位动画师看第二角度和骨架复核。若比较偏好，另行交换 A/B 播放次序。保留两人的初始意见、最终裁决和不可判原因。
4. 给正常组和受控故障组各自计数。报告故障错放数/已标注故障数、合格错杀数/已标注合格数、弃权数/总数，并列相机、动作和角色骨架分组。多帧同一次变形、多骨同一个肢体故障，只作为同一次片段/动作样本。合成自测证明工具对指定扰动有反应；生产发布结论还需要不同角色、动作和目标设备的真实运行证据。

| 可复现的合成对照 | 预期区分 |
| --- | --- |
| 两骨保持长度且连接，0–150° 的受控屈肘 | 几何通过；动作语义由另一用例判断。 |
| 从第一帧起加长 20%，候选同时篡改自报静止长度与阈值 | 采用外部基准时检出 20% 骨长偏差。 |
| 前臂和手一起平移 3 cm，长度保持；另试共享、缺失端点 | 独立端点检出约 3 cm 缝隙；共享或缺失端点的连接结果弃权。 |
| 附件骨正常偏移 5 cm，独立测得的父骨附件与子骨近端重合；另试附件脱离或未采附件 | 有正确附件轨迹时测得零缝隙，偏移的绑定不触发断肢；真实脱离 3 cm 报失败，缺附件或连接未标定则弃权。 |
| 175° 过弯、一个采样间隔由 0° 跳至 90° | 分别触发关节范围和时间跳变检查。 |
| 删除中间帧，或让轨迹早于预期窗口结束 | 稀疏区间不参与速度推算，整段通过结论撤回。 |

运行 `test_motion.py` 可复现以上输入。网页端 `pose.js` 还提供 `idle`、`nod`、`wave` 三个程序化动作，以及 `stretch`、`detach`、`jitter` 三类可切换故障；分别导出后可经相同 CLI 复核。标准化人形动画可以携带骨骼、表情等通道，目标角色的骨架和变换会影响最终动作，因此验收应落在目标 App 的实际渲染输出上。[VRM Consortium 动画规范](https://github.com/vrm-c/vrm-specification/tree/master/specification/VRMC_vrm_animation-1.0)

## 社区实现怎样用于独立对照

| 开源实现 | 可复用的方法 | 本项目接入与验证范围 |
| --- | --- | --- |
| Khronos glTF Validator | 骨架、蒙皮或动作作为 glTF 交付时，先校验文件规范并保留诊断报告。通过格式检查后，再用实际变换和画面评估连接、变形和穿模。[项目仓库](https://github.com/KhronosGroup/glTF-Validator) | 当前动作 CLI 接收 JSON 轨迹，本次未安装或运行 glTF Validator。 |
